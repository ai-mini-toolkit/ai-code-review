# Story 7.2: 实现 Git 平台评论通知 (Git Platform Comment Notification)

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a 开发者 (Developer),
I want 在 PR/MR 中看到 AI 代码审查摘要评论,
so that 我能在代码审查界面直接查看审查结果，无需切换到其他工具。

### AC2: GitHub PR 评论服务
- 在 integration 模块创建 `GitHubPRCommentService` 接口：
  - `postComment(String repoUrl, Integer prNumber, String markdownBody): Long`（返回 comment ID）
- 创建 `GitHubPRCommentServiceImpl`：
  - 调用 GitHub REST API: `POST /repos/{owner}/{repo}/issues/{number}/comments`
  - 请求头：`Authorization: Bearer {token}`, `Accept: application/vnd.github+json`
  - 请求体：`{"body": "<markdown>"}`
  - 使用已有的 `HttpClient` bean 和 `git.platform.github.token` 配置
  - 使用 `GitHubUrlUtils.parseOwnerRepo()` 提取 owner/repo
  - Token 未配置时 WARN 日志并返回 null

### AC3: GitLab MR 评论服务
- 在 integration 模块创建 `GitLabMRCommentService` 接口：
  - `postComment(String repoUrl, Integer mrIid, String markdownBody): Long`（返回 note ID）
- 创建 `GitLabMRCommentServiceImpl`：
  - 调用 GitLab REST API: `POST /api/v4/projects/{id}/merge_requests/{iid}/notes`
  - 请求头：`PRIVATE-TOKEN: {token}`
  - 请求体：`{"body": "<markdown>"}`
  - 使用已有的 `HttpClient` bean 和 `git.platform.gitlab.token` / `git.platform.gitlab.base-url` 配置
  - 使用 `GitLabUrlUtils.parseProjectPath()` 提取项目路径
  - Token 未配置时 WARN 日志并返回 null

### AC4: AWS CodeCommit PR 评论服务（Stub）

  - `postComment(String repoUrl, String prId, String markdownBody): String`
- 创建 `AWSCodeCommitCommentServiceImpl`（Stub）：
  - 记录 WARN 日志 "AWS CodeCommit comment not yet implemented"
  - 返回 null

### AC5: Git 平台评论通知编排服务
- 在 service 模块创建 `GitCommentNotificationService` 接口：
  - `postReviewComment(Long taskId): void`
- 创建 `GitCommentNotificationServiceImpl`：
  1. 通过 `reviewTaskRepository.findById()` 查找任务
  2. 验证 `task.getPrNumber() != null`（仅 PR/MR 任务）
  3. 通过 `notificationConfigRepository.findByProjectId()` 查找配置
  4. 验证 `config.getCommentEnabled() == true`
  5. 调用 `reviewReportService.generateReport(taskId)` 生成报告
  6. 调用 `buildCommentBody()` 构建精简 Markdown 评论内容
  7. 根据 `task.getProject().getGitPlatform()` 分发到对应平台服务
  8. 所有异常捕获并记录 WARN 日志，不阻塞主流程

### AC6: 评论内容格式
- 评论 Markdown 格式包含：
  - 标题行：`## :robot: AI Code Review` 标识
  - 审查状态：`**Status:** Passed / Failed`
  - 摘要表格：严重性分布（Severity | Count 表格）
  - 阈值验证结果：`Threshold: Passed` 或 `Threshold: **FAILED** — N violation(s)`
  - 高严重度问题列表：TOP 5 issues（CRITICAL + HIGH，按严重性排序）
  - 完整统计：Total issues, by category
  - 脚注：`*Generated by AI Code Review*`
- GitHub PR 评论长度限制 65536 字符，超出时截断并添加 `...（truncated）`
- GitLab MR Note 长度限制类似，同样处理

## Dev Notes

### 架构模式

**模块分布（沿用 Story 6.3/6.4/7.1 既定模式）**：
- **integration 模块**：`GitHubPRCommentService`、`GitLabMRCommentService`、`AWSCodeCommitCommentService` — HTTP API 调用层
- **service 模块**：`GitCommentNotificationService` — 业务编排层（查配置 → 生成内容 → 分发平台）
- **repository 模块**：`NotificationConfigEntity` 更新 + Flyway 迁移
- **common 模块**：`NotificationConfigDTO` 更新

**复用已有组件**：
- `HttpClient` bean（已在 integration 模块配置）
- `GitHubUrlUtils.parseOwnerRepo()` — 提取 GitHub owner/repo
- `GitLabUrlUtils.parseProjectPath()` — 提取 GitLab URL-encoded project path
- `ReviewReportService.generateReport()` — 生成报告 DTO
- `NotificationConfigRepository.findByProjectId()` — 查询通知配置
- `ReviewTaskRepository.findById()` — 查询任务详情

### API 端点参考

**GitHub Issues Comments API** ([Source: docs.github.com]):
```
POST https://api.github.com/repos/{owner}/{repo}/issues/{issue_number}/comments
Headers: Authorization: Bearer {token}, Accept: application/vnd.github+json
Body: {"body": "<markdown>"}
Response: {"id": 12345, "html_url": "https://github.com/..."}
```
注意：GitHub 中 PR 评论使用 Issues API（PR 即 Issue 的子类型）。

**GitLab Merge Request Notes API** ([Source: docs.gitlab.com]):
```
POST {base_url}/api/v4/projects/{id}/merge_requests/{merge_request_iid}/notes
Headers: PRIVATE-TOKEN: {token}
Body: {"body": "<markdown>"}
Response: {"id": 67890, "body": "..."}
```

**AWS CodeCommit** (Stub):
- 真实实现需要 AWS SDK `CodeCommitClient.postCommentForPullRequest()`
- 当前版本仅实现 Stub，与 Epic 6 Story 6.4 保持一致

### 评论内容生成策略

**不使用 `ReviewReportService.renderMarkdown()`** — 完整报告对 PR 评论太长。
**自建精简版 `buildCommentBody()`**：
- 从 `ReviewReportDTO` 提取 summary、issues、metadata
- 按严重性排序后取 TOP 5 issues
- 构建紧凑的 Markdown 格式（适合 PR/MR 评论场景）
- GitHub 限制 65536 字符，GitLab 类似

### 关键技术约束

1. **仅 PR/MR 任务**：`task.getPrNumber() != null` 才发送评论。PUSH 类型任务无 PR 可评论。
2. **`-parameters` 未启用**：使用 `@Value("${git.platform.github.token:}")` 等，无 SpEL 参数名问题。
3. **循环依赖防护**：`GitCommentNotificationService` 注入 `ReviewReportService`（单向依赖，无循环）。在 `ReviewResultServiceImpl` 中使用 `@Lazy` 注入 `GitCommentNotificationService`。
4. **非阻塞模式**：与 Email 通知一致，所有平台 API 调用异常仅记录 WARN 日志。
5. **Token 配置**：复用 `git.platform.github.token` 和 `git.platform.gitlab.token`（Story 6.3/6.4 已配置）。

### 前序 Story 教训（来自 Story 7.1 Code Review）

- **M1（重复通知）**：violation 和 complete 通知互斥发送。评论通知同理 — 不论阈值结果，只要 isSuccess=true 就发送一次评论。
- **M3（缓存）**：EmailNotificationService 中已缓存 project-level SMTP sender。平台评论服务无需缓存（使用全局 token）。
- **M4（输入验证）**：prNumber 为 null 时静默跳过，不需要额外验证。
- **H2（集成测试）**：确保 ReviewResultServiceImplTest 有评论通知集成测试。
